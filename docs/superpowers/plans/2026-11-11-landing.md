# 연수온 landing page implementation plan

**Goal:** Implement SPEC.md as a complete Korean public-sector landing page and private feedback service.
**Architecture:** Static HTML/CSS/ES modules in public; a Vercel Node function with a shared pure validator and private Blob storage. No frontend framework, external font, analytics, or public read API.
**Tech stack:** Node built-in test runner, vanilla JavaScript, @vercel/blob as the only direct dependency.
**Spec:** [SPEC.md](../../../SPEC.md)

## Constraints and decisions
- Work in the supplied repository: it has no commits; do not commit, deploy, or modify either supplied distribution file.
- Public-service visual direction: ivory, deep navy, muted blue, small yellow accents; original editorial layout and an explicitly illustrative operations diagram.
- Large Korean text, semantic landmarks, native form controls, visible focus, reduced-motion support, responsive layout.
- Download safety summary immediately precedes an explicit file link; complete notices and checksum remain available below.
- Experience, feature selection, open feedback, interview, and contact are optional. Institution, usage stage, satisfaction, ease, recommendation are required.
- Exact trusted Origin checking, 32 KiB byte limit, strict allowlist, private JSON objects named using server UUID/time; never return or log contact data.

## Review focus
- Missing or zero recommendation must not become an accidental default answer.
- Timeout/storage failure must preserve answers and release the submission lock.
- Revoking interview consent must clear and disable contact; fallback copies omit contact.
- Chunked/multibyte body limits and spoofed or lookalike origins must be rejected.
- Download policy must preserve the downloaded HTML's own execution when saved locally without changing the supplied asset.
